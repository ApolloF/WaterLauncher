WaterLauncher 1.0: the first full release. It now installs like any other Windows app, keeps itself up to date, and can start with Windows.

**Install**

- Download **WaterLauncher-setup.exe** and run it. It installs for your Windows account only (in `%LOCALAPPDATA%\Programs\WaterLauncher`), so it needs no administrator rights, and adds a Start menu and desktop shortcut.
- Coming from a preview: your library, settings, keys and art carry over as they are. You can delete the old `WaterLauncher.exe` once the installed one runs.
- Prefer no installer? `WaterLauncher.exe` still works on its own, from any folder you can write to.
- Uninstalling (Settings → Apps) removes the program and its shortcuts. It asks whether to delete your library and settings too; your games and their saves are never touched.

**Updates**

- *Settings → General → Keep WaterLauncher up to date* (on by default). WaterLauncher checks GitHub twice a day, downloads a new version in the background, and installs it the next time it starts. *Restart and update* installs it right away.
- A downloaded update is only used when it matches the SHA-256 published with the release, and it only ever comes from this repository's releases. Once WaterLauncher is signed, an update must be signed by the same publisher too.
- Nothing is checked or downloaded while you play. An update that fails to install isn't retried on its own; *Settings → About* says so and offers to try again.
- A copy that isn't installed updates by replacing its own exe. If its folder isn't writable, WaterLauncher tells you a new version is out instead.
- Previews (versions like v1.1.0-beta.1) never arrive as updates.

**Start with Windows**

- *Settings → General → Start with Windows*: WaterLauncher waits in the tray when you sign in, so the PS button opens it right away and your library is up to date.
- If you turned it off in Task Manager's *Startup apps*, Settings says so.

**Faster and lighter**

- Repeat scans are about ten times faster: WaterLauncher remembers which folders hold games and how big they are, instead of walking them every time.
- Merging a large owned library (thousands of Steam games) into a scan went from about a tenth of a second to under a millisecond.
- With no controller connected, the controller layer checks for one four times a second instead of 125 times. Idle CPU use is now too small to measure.
- While a game runs, scans, art downloads and store-account updates wait until you're done.
- New art, favorites and playtime update the one game on screen instead of reloading the whole library.
- Art no game uses anymore is cleaned up.

**Fixes**

- Quitting WaterLauncher could, rarely, save the library twice at once and damage it. Saves no longer overlap, and if `library.json` is ever damaged, the copy from the previous start is used.
- Quitting in the middle of a game now keeps the last minute of playtime.
- An add-on that stopped reading its input could make WaterLauncher wait forever.

**For developers**

- `WaterLauncher.exe --tray` starts in the tray; `--quit` closes a running WaterLauncher (the installer uses it). A second start now hands its arguments to the running copy before opening the library.
- The build publishes `WaterLauncher-setup.exe` next to `WaterLauncher.exe`, each with a `.sha256`. `github.com/ApolloF/WaterLauncher/releases/latest/download/WaterLauncher-setup.exe` always points at the newest installer.
- Code signing is wired up but needs a certificate; see [docs/SIGNING.md](https://github.com/ApolloF/WaterLauncher/blob/main/docs/SIGNING.md). Until then, Windows SmartScreen may warn on first run: choose *More info → Run anyway*.
